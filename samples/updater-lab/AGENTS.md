# Updater Lab — guide for coding agents

Kotlin Multiplatform + Compose Multiplatform client generated by create-kmp-app
(template `client-2026.08-v1`). Package `saien.updater.lab`. Targets: macos,windows.

## Layout

- `shared/` — Compose UI and logic for every target (`src/commonMain`), tests in `src/commonTest`.
- `desktopApp/` — Compose Desktop application; `Main.kt` opens the window, jpackage builds installers.

Shared UI and logic live in `shared/src/commonMain`. Platform-specific code goes into
`shared/src/<androidMain|jvmMain|iosMain>` behind `expect`/`actual` declarations or explicit
dependency wiring; the platform modules only host lifecycle, packaging, and entry points.

## Build, run, check

- `create-kmp-app run desktop` — runs the Compose Desktop window through Gradle.

- Fast feedback: `./gradlew :shared:jvmTest` runs the shared tests without any device.
- Everything this host can build: `create-kmp-app verify`.
- After a UI change: `create-kmp-app run <target> --no-logs && create-kmp-app screenshot <target>`, then look at
  the PNG path it prints. Ctrl-C on `create-kmp-app run` only stops the log stream.
- `create-kmp-app doctor` explains any missing tool; `create-kmp-app doctor --fix` installs it after one
  confirmation. Do not install SDKs by hand before running it.

## Adding a feature

1. Create `shared/src/commonMain/kotlin/saien/updater/lab/<feature>/` with a `<Feature>Screen` composable. Put logic that needs no Compose into plain classes that receive their collaborators as constructor parameters.
2. `App.kt` is the root composable; place the screen there. For several screens, regenerate with the navigation integration or add Navigation 3 yourself.
3. Test the plain classes in `shared/src/commonTest` and run `./gradlew :shared:jvmTest`.
4. Run on a target, take a screenshot, and check it before finishing.

## Rules

- `gradle/libs.versions.toml` is one tested version tuple. Do not bump a single library; a newer
  create-kmp-app release moves the whole tuple.
- Keep UI and logic in `commonMain`. When a platform API is unavoidable, add an `expect`
  declaration and an `actual` in every platform source set this project has.

- Never commit `local.properties`, keystores, or anything under `build/`.
